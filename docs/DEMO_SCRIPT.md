# ARIS 90-second portfolio demo outline

This outline is a reference for the project owner, not a claim that every roadmap feature is complete.

## 0–12 seconds — Problem and goal

Show the centered ARIS energy orb and audio-reactive orbital animation. Explain: “ARIS is my Python Mechatronics portfolio beta. It connects computer vision, 3D visualization, safe desktop automation, and a path toward future 3D-printed wearables.”

## 12–30 seconds — Architecture

Briefly show the repository modules in VS Code and the README architecture diagram. Mention PySide6, MediaPipe, OpenGL, local intent routing, and JSON persistence.

## 30–55 seconds — 3D and hand vision

Speak naturally without touching the UI and request two models. Show each background-free hologram appearing at the ARIS core, use an open five-finger hand to move one aside, click the other to select it, then pinch to demonstrate one smooth horizontal viewing orbit. Say `phóng to Rasengan 30%` to demonstrate precise local voice-only zoom. Keep the raw camera hidden to emphasize privacy.

## 55–72 seconds — Assistant actions and live research

Demonstrate one model command and one safe desktop action, for example `show Minato Kunai` and `open VS Code`. Say `close Rasengan` to remove only one hologram, then `end` to clear the remaining models. Show that unsupported commands are rejected rather than executed.
Open one short source-cited research panel, drag it aside, and pinch vertically once to show the
scroll interaction. Do not linger on a live API call if network latency would disrupt the recording.

## 72–84 seconds — Engineering proof

Show the terminal with Ruff and Pytest passing. Briefly mention the fixed allowlist, API opt-in, camera release behavior, and Vietnamese docstrings used to study the logic.

## 84–90 seconds — Future direction

Close with: “The next Mechatronics step is calibrated hand measurement, parametric CAD export, and a safe non-functional 3D-printed fit prototype.”

## Recording checklist

- Record at 1080p with browser/API keys and personal notifications hidden.
- Use a clean repository state and readable terminal font.
- Avoid copyrighted music or film clips.
- Do not describe relative hand proportions as millimeter-accurate.
- Add GitHub and demo-video links to the README only after the final review.
